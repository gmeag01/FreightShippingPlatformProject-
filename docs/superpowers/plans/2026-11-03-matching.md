# 차주 매칭(matching) 도메인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 차주(`DRIVER`)가 등록됨(`REGISTERED`) 상태의 의뢰 목록을 차종별로 조회하고, 차량·중량 불일치 경고 확인 및 `@Version` 낙관적 락 기반 동시 수락 방지를 거쳐 오더를 수락하거나 배차를 취소하는 백엔드 API와 통합 테스트를 완성한다.

**Architecture:** `com.freight.matching` 도메인은 컨트롤러(`MatchingController`)와 서비스(`MatchingService`), DTO로 구성한다. 도메인 간 규칙에 따라 `OrderRepository`나 `VehicleRepository`를 직접 참조하지 않고 `OrderService`, `VehicleService`, `MemberService`를 호출한다.

**Tech Stack:** Java 21, Spring Boot 3.5.x, Spring Data JPA (`@Version` 낙관적 락), Spring Security (`@PreAuthorize("hasRole('DRIVER')")`), JUnit 5, AssertJ

**Spec:** `docs/superpowers/specs/2026-11-02-freight-platform-design.md` (5장 차주 매칭), `docs/superpowers/plans/2026-11-02-roadmap.md`

- [ ] **Step 1: 실패하는 단위/통합 테스트 작성 (`MatchingServiceTest`)**
  - `listOpenOrders_filtersByRegisteredAndVehicleType_andOrdersByPickupAtAsc`: `REGISTERED` 상태만, `pickupAt` 오름차순, `region`만 포함하고 상세주소는 노출하지 않음

  - `acceptOrder_whenMismatchConfirmed_succeeds`: `confirmMismatch=true`이면 정상 배차(`ASSIGNED`)
